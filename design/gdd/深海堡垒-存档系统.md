## Overview

存档系统管理自动存档（60秒间隔）、手动存档/加载（F5/F9快捷键）、5槽位多存档管理、存档数据恢复、版本迁移、通关后存档清理和可选加密。系统通过SaveData类驱动存档数据结构，使用JSON格式序列化，存档路径为`user://save_data.json`。自动存档避开战斗和危险状态，关键事件（完成任务、击败Boss）后立即存档，游戏启动时自动检测并恢复存档进度。

---

## Player Fantasy

玩家应感受到：
- **自动存档的安全网** — 每60秒自动保存，不用担心意外退出丢失进度
- **手动存档的自主权** — 按F5随时保存关键决策点，F9快速加载回退
- **多槽位的灵活性** — 5个存档槽位，不同进度/难度的存档互不干扰
- **通关后重来的新鲜感** — 通关后自动删除存档，鼓励全新挑战而非重复利用

## Detailed Rules

### 存档触发时机

| 触发时机 | 存档类型 | 说明 |
|---------|---------|------|
| 定期触发 | 自动存档 | 每60秒自动保存（AUTOSAVE_INTERVAL） |
| 关键事件后 | 自动存档 | 完成任务、击败Boss后立即保存 |
| 玩家主动 | 手动存档 | 按F5键存档 |
| 退出游戏前 | 自动存档 | 游戏退出时自动保存 |

### 存档安全优化

| 优化规则 | 说明 |
|---------|------|
| 避免战斗存档 | 战斗激烈时不触发自动存档 |
| 避免危险状态 | 深海高压区（HP<20%）不触发自动存档 |
| 安全区域优先 | 在安全区域自动存档 |

### 存档数据结构

| 存档字段 | 类型 | 说明 |
|---------|------|------|
| player_position | Vector3 | 当前所在位置坐标 |
| player_health | float | 当前HP值 |
| player_stamina | float | 当前体力值 |
| player_flashlight_battery | float | 手电筒电池剩余电量 |
| keys_collected | Array[String] | 已收集钥匙ID列表 |
| keys_required | int | 所需钥匙总数 |
| enemies_killed | int | 已击败敌人数量 |
| current_level | String | 当前所在海域/关卡名称 |
| timestamp | String | 存档保存时间（ISO 8601） |
| resources | Dictionary | 仓库资源数量 {iron, copper, fuel, ...} |
| facility_states | Dictionary | 船上各设施状态 {facility_id: {hp, level, ...}} |
| play_time_seconds | float | 游戏总时长 |
| difficulty | String | 当前难度等级 |
| save_version | int | 存档数据版本号 |

### 存档流程

**自动存档**:
```
计时器运行 → 每60秒触发 → 检查安全状态 →
更新存档数据 → 序列化JSON → 保存到文件 →
显示存档提示 → 继续游戏
```

**手动存档**:
```
玩家按F5 → 检查安全状态 → 更新存档数据 →
序列化JSON → 保存到文件 → 显示"游戏已保存" →
继续游戏
```

**手动加载**:
```
玩家按F9 → 检查存档是否存在 → 读取JSON文件 →
解析数据 → 验证数据完整性 → 应用存档数据 →
显示"存档已加载" → 发送信号更新UI
```

### 启动时存档检测

```
游戏启动 → 检查存档文件是否存在 →
存在：读取JSON → 等待场景加载（0.1秒）→
解析数据 → 恢复玩家状态 → 恢复进度 →
发送信号更新UI → 继续游戏
不存在：正常开始新游戏
```

### 数据恢复流程

| 步骤 | 操作 |
|------|------|
| 读取存档 | 从JSON文件读取并解析 |
| 等待加载 | 等待场景加载完成（0.1秒） |
| 恢复位置 | player.global_position = 存档位置 |
| 恢复属性 | player.current_health/stamina/flashlight_battery = 存档值 |
| 恢复进度 | 钥匙进度、资源数量、设施状态 |
| 发送信号 | health_changed, stamina_changed, flashlight_battery_changed |

### 多存档槽位设计

| 属性 | 值 |
|------|-----|
| 槽位数量 | 5个（Slot 1-5） |
| 每槽独立 | 每个槽位独立存档 |
| 槽位信息 | 存档时间、关卡/海域、游戏时长、难度等级、钥匙进度 |
| 自动存档 | 使用最近使用的槽位 |
| 新游戏 | 选择空槽或覆盖已有存档 |

### 存档版本管理

| 版本 | 迁移规则 |
|------|---------|
| v1 | 初始版本 |
| v1→v2 | 新增字段填充默认值 |
| v2→v3 | 废弃字段忽略+记录日志 |
| 跨多版本 | 逐级迁移 |
| 无法迁移 | 提示玩家并保留旧档 |

### 存档加密方案

| 方案 | 说明 | 适用场景 |
|------|------|---------|
| XOR混淆 | 简易加密，防简单修改 | 非敏感存档，仅防作弊 |
| AES-128加密 | 密钥硬编码，加密整个JSON | 推荐方案 |
| SHA-256校验和 | 文件末尾附加校验和 | 数据完整性验证 |

### 通关后存档清理

| 触发条件 | 玩家通关（打开出口门逃脱） |
|---------|-------------------------|
| 清理流程 | 删除存档文件 → 重置存档数据 |
| 清理目的 | 避免重复使用通关存档，鼓励重新挑战 |

### 手动删除存档

| 步骤 | 操作 |
|------|------|
| 触发 | 设置界面选择"删除存档" |
| 确认 | 弹出确认对话框 |
| 执行 | 删除存档文件 → 重置数据 |
| 结果 | 下次游戏从头开始 |

## Formulas

### 自动存档间隔

```
AUTOSAVE_INTERVAL = 60秒  # 可通过DifficultyConfig调整

实际存档间隔 = AUTOSAVE_INTERVAL × 难度存档间隔系数
难度存档间隔系数: 简单=0.5(30秒), 普通=1.0(60秒), 困难=2.0(120秒), 深渊=4.0(240秒)
```

### 存档安全状态判定

```
is_safe_to_autosave():
    return NOT in_combat
       AND player_health > 0.20  # HP>20%
       AND NOT in_deep_sea_pressure_zone
       AND NOT during_boss_fight
       AND game_is_not_paused
```

### 存档数据序列化

```
save_data = {
    "save_version": SAVE_DATA_VERSION,
    "player_position": player.global_position,
    "player_health": player.current_health,
    "player_stamina": player.current_stamina,
    "player_flashlight_battery": player.flashlight_battery,
    "keys_collected": keys_collected_ids,
    "keys_required": keys_required_count,
    "enemies_killed": enemies_killed_count,
    "current_level": current_level_name,
    "timestamp": Time.get_datetime_string_from_system(),
    "play_time_seconds": total_play_time,
    "difficulty": current_difficulty,
    "resources": resource_dict,
    "facility_states": facility_state_dict
}

# 加密（如启用）
if encryption_enabled:
    save_data = encrypt(save_data, encryption_key)

# 写入文件
file = FileAccess.open("user://save_data.json", FileAccess.WRITE)
file.store_string(JSON.stringify(save_data))
file.close()
```

### 存档数据加载

```
file = FileAccess.open("user://save_data.json", FileAccess.READ)
json_string = file.get_as_text()
file.close()

# 解密（如启用）
if encryption_enabled:
    json_string = decrypt(json_string, encryption_key)

# 校验和验证（如启用）
if checksum_enabled:
    verify_checksum(json_string)

save_data = JSON.parse_string(json_string)

# 版本迁移
if save_data.save_version < SAVE_DATA_VERSION:
    save_data = migrate_save_data(save_data)

# 数据恢复
player.global_position = save_data.player_position
player.current_health = save_data.player_health
player.current_stamina = save_data.player_stamina
player.flashlight_battery = save_data.player_flashlight_battery

# 发送信号
emit_signal("health_changed", player.current_health)
emit_signal("stamina_changed", player.current_stamina)
emit_signal("flashlight_battery_changed", player.flashlight_battery)
```

### 存档版本迁移

```
migrate_save_data(save_data):
    current_version = save_data.save_version
    while current_version < SAVE_DATA_VERSION:
        migration = get_migration(current_version, current_version + 1)
        if migration == null:
            show_error("无法迁移存档，版本跨度过大")
            return null
        save_data = migration.apply(save_data)
        current_version += 1
    save_data.save_version = SAVE_DATA_VERSION
    return save_data
```

### 存档校验和

```
# 写入时
checksum = SHA256.hash(json_string.to_utf8_buffer())
file.store_string(json_string + "|" + checksum.to_hex())

# 读取时
parts = file_content.split("|")
stored_checksum = parts[1]
computed_checksum = SHA256.hash(parts[0].to_utf8_buffer()).to_hex()
if stored_checksum != computed_checksum:
    show_error("存档数据已损坏")
    return null
```

## Edge Cases

1. **存档文件不存在**: 游戏启动时检测不到存档文件，正常开始新游戏，不报错。
2. **存档数据损坏**: JSON解析失败或校验和不匹配，提示"存档已损坏，请重新开始"，不加载任何数据。
3. **存档版本过旧无法迁移**: 跨越多个版本且缺少中间迁移规则，提示玩家"存档版本过旧，无法兼容"，保留旧档不删除。
4. **战斗激烈时自动存档触发**: 自动存档被跳过（is_safe_to_autosave返回false），等待下次安全时机。
5. **存档写入中途崩溃/断电**: 使用临时文件+原子替换策略（先写到.tmp，再rename覆盖），避免产生半写入的损坏文件。
6. **手动加载时场景未加载完成**: 等待场景加载完成（0.1秒延迟）后再应用存档数据，避免空引用。
7. **5个存档槽位全部占满**: 新游戏时提示玩家选择一个已有槽位覆盖，或清理旧存档。
8. **通关后删除存档失败**: 文件权限或路径问题导致删除失败，记录错误日志，下次启动时仍可检测到旧存档并提示清理。
9. **加密存档但密钥变更**: 游戏更新后密钥变化导致无法解密旧存档，提示"存档格式不兼容"，保留旧档。
10. **多槽位同时自动存档冲突**: 自动存档只写入最近使用的槽位，不会同时写多个槽位。手动切换槽位后自动存档跟随。

## Tuning Knobs

| 参数 | 当前值 | 安全范围 | 影响 |
|------|--------|---------|------|
| 自动存档间隔(普通) | 60秒 | 30-120秒 | 影响存档频率和数据安全性 |
| 自动存档间隔(简单) | 30秒 | 15-60秒 | 影响休闲模式安全网 |
| 自动存档间隔(困难) | 120秒 | 60-180秒 | 影响硬核模式容错度 |
| 自动存档间隔(深渊) | 240秒 | 120-360秒 | 影响极限模式容错度 |
| 存档槽位数量 | 5个 | 3-10个 | 影响玩家存档灵活性 |
| 安全存档HP阈值 | 20% | 10-40% | 影响低HP时存档安全性 |
| 存档数据版本号 | v1 | 随更新递增 | 影响旧版存档兼容性 |
| 场景加载等待时间 | 0.1秒 | 0.05-0.5秒 | 影响存档恢复稳定性 |
| 加密方案 | AES-128 | 可选XOR/AES-128/无 | 影响存档防修改能力 |
| 校验和算法 | SHA-256 | 可选CRC32/SHA-256/无 | 影响数据完整性检测 |
| 存档文件格式 | JSON | JSON/Binary | 影响可读性和文件大小 |
| 存档提示显示时长 | 2秒 | 1-5秒 | 影响反馈可见性 |
| 版本迁移最大跨度 | 2个版本 | 1-5个版本 | 影响旧档兼容性 |
| 通关后清理确认 | 自动 | 自动/手动确认 | 影响清理安全性 |

## Acceptance Criteria

- [ ] 游戏每60秒（普通难度）自动触发一次存档，保存JSON到`user://save_data.json`
- [ ] 按F5键手动存档，显示"游戏已保存"提示+存档时间
- [ ] 按F9键手动加载存档，恢复玩家位置、HP、体力、电量、资源、钥匙进度
- [ ] 游戏启动时自动检测存档，存在则恢复进度，不存在则开始新游戏
- [ ] 战斗激烈时（in_combat=true）自动存档被跳过，不触发保存
- [ ] 玩家HP低于20%时自动存档被跳过，等待安全时机
- [ ] 存档数据包含save_version字段，支持v1→v2版本迁移
- [ ] 5个存档槽位各自独立，自动存档使用最近使用的槽位
- [ ] 通关后自动删除当前槽位存档文件
- [ ] 设置界面提供"删除存档"选项，需要确认后执行
- [ ] 存档损坏时（JSON解析失败/校验和不匹配）提示"存档已损坏"，不加载数据
- [ ] 存档写入使用临时文件+原子替换策略，避免半写入损坏
- [ ] 存档恢复后发送health_changed/stamina_changed/flashlight_battery_changed信号更新UI
- [ ] 所有存档参数（存档间隔、槽位数量、安全阈值、加密方案）可通过配置文件调整，无需修改代码
