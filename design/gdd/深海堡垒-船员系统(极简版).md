## Overview

船员系统采用极简设计，以"船员总数"为核心概念，管理船员数量（健康/受伤/死亡）、船员效率（设施运作受健康船员数影响）、船员招募（港口/救援/NPC加入）、船员死亡（深度相关概率计算）、船员受伤（自动恢复/医疗室加速）、船员分配（手动/自动/紧急调配）、船员士气（影响效率修正）、船员打捞（深度相关成功率）、NPC船员（好感度系统）和船员结局关联。MVP版本不做船员个体化，后续版本可扩展为完整船员系统。

---

## Player Fantasy

玩家应感受到：
- **船员管理的策略深度** — 8个船员如何分配到6个设施？自动分配一键搞定，但紧急调配需要手动决策
- **船员死亡的真实代价** — 深水区潜艇被击毁90%死亡概率，每次深海探索都有风险
- **打捞决策的紧张感** — "打捞成功率50%，资源消耗氧气罐×2+电池×1 — 开始打捞还是放弃？"
- **士气系统的微妙影响** — 船员死亡士气-10，食物不足-5，高士气+15%效率，低士气可能叛逃

## Detailed Rules

### 核心概念

| 原则 | 说明 |
|------|------|
| 抽象化 | 船员是"数量"，不是"个体" |
| 效率驱动 | 船员数量影响设施效率 |
| 死亡代价 | 船员死亡→数量减少→效率降低 |
| 招募成本 | 消耗资源招募新船员 |
| 可扩展 | 后续版本可自然扩展为完整船员系统 |

### 船员数据结构

| 字段 | 类型 | 说明 |
|------|------|------|
| total | int | 当前船员总数 |
| maxCapacity | int | 最大船员容量（受居住舱等级影响） |
| healthy | int | 健康（可工作）船员数 |
| injured | int | 受伤船员数（暂时无法工作） |
| dead | int | 死亡船员数 |
| morale | int | 当前士气值（0-100） |

### 船员容量

| 居住舱等级 | 船员容量 |
|-----------|---------|
| Lv1 | 10人 |
| Lv2 | 15人 |
| Lv3 | 20人 |
| Lv4 | 25人 |
| Lv5 | 30人 |

### 船员效率系统

**核心公式**:
```
设施效率 = 基础效率 × min(1.0, 健康船员数 / 最优船员数)
```

| 设施 | 最优船员数 | 最低需求 | 低于最低后果 |
|------|-----------|---------|-------------|
| 炮台 | 2人 | 1人 | 精度降低、射速减慢 |
| 维修设施 | 3人 | 1人 | 维修速度极慢 |
| 潜艇操控 | 1人 | 1人 | 无法下潜 |
| 医疗室 | 1人 | 1人 | 无法治疗 |
| 工坊 | 1人 | 1人 | 制造速度降低 |
| 资源采集 | 2人 | 1人 | 采集极慢 |

**效率示例**（炮台，最优2人）:

| 健康船员分配 | 效率 |
|-------------|------|
| 0人 | 0%（无法运作） |
| 1人 | 50%（效率减半） |
| 2人 | 100%（最优） |
| 3人 | 100%（多余不增加） |

### 船员招募

| 方式 | 消耗 | 条件 |
|------|------|------|
| 港口招募 | 金币×100/人 | 需在港口/避难所 |
| 救援幸存者 | 无消耗 | 需救援任务 |
| NPC加入 | 无消耗 | 完成NPC任务 |

**招募限制**: 不超过maxCapacity，需要足够金币，需在港口/避难所附近。

### 船员死亡系统

**死亡触发条件**:

| 死亡原因 | 死亡概率 | 说明 |
|---------|---------|------|
| 潜艇被击毁 | 30-90% | 深度越深概率越高 |
| 氧气耗尽 | 30-50% | 距离船越远概率越高 |
| 设施爆炸 | 20-40% | 弹药库/动力室爆炸 |
| 登船入侵失败 | 10-30% | 内部防守失败 |

**深度死亡概率**（潜艇被击毁）:

| 深度 | 死亡概率 |
|------|---------|
| 浅水区(0-100m) | 30% |
| 深水区(100-300m) | 50% |
| 深海区(300-500m) | 70% |
| 深渊区(500m+) | 90% |

**死亡计算**:
```
死亡数 = 潜艇船员数 × 死亡概率 × 随机因子
```

### 船员受伤系统

| 受伤原因 | 受伤概率 |
|---------|---------|
| 设施损坏 | 设施损坏程度 × 10% |
| 登船入侵 | 防守失败程度 × 20% |
| 战斗波次 | 波次强度 × 5% |

**受伤后果**: 暂时无法工作（不计入healthy），5-10分钟自动恢复，医疗室加速恢复（需船员在医疗室）。

### 船员分配系统

**分配流程**:
1. 玩家打开设施管理界面
2. 查看设施状态和船员分配
3. 点击"分配船员"
4. 选择分配数量（1-最大可用数）
5. 确认分配 → 设施效率更新

**自动分配优先级**:
1. 潜艇驾驶（必须1人）
2. 炮台（至少每个炮台1人）
3. 维修设施（至少1人）
4. 医疗室（如果有受伤船员）
5. 工坊（如果有建造需求）
6. 资源采集（剩余船员）

**紧急调配**（波次来袭）: 快速调配界面提供预设策略（均衡防御/重点防御/维修优先）。

### 船员打捞系统

**打捞成功率**:
```
基础打捞率 = 60%
深度修正 = -10% × (深度 / 100m)
设备修正 = +5% × 打捞设备等级
船员修正 = +20%（NPC船员）
天气修正 = ±10%（根据海况）
幸运修正 = +5% × (幸运值 / 10)

最终打捞率 = max(10%, min(95%, 基础 + 所有修正))
```

| 深度 | 基础成功率 | 打捞时间 | 资源消耗 |
|------|-----------|---------|---------|
| 0-50m | 90% | 1分钟 | 无 |
| 50-100m | 80% | 1分钟 | 无 |
| 100-200m | 65% | 3分钟 | 氧气罐×1 |
| 200-300m | 50% | 5分钟 | 氧气罐×2, 电池×1 |
| 300-500m | 35% | 8分钟 | 氧气罐×3, 电池×2 |
| 500m+ | 20% | 12分钟 | 氧气罐×5, 电池×3, 金币×50 |

**浅水区(0-100m)**: 潜艇被击毁默认全部生还（自动打捞）。

### 船员与结局关联

**船员存活率影响结局**:

| 存活率 | 结局等级 | 结局描述 |
|--------|---------|---------|
| 90-100% | S级 | 全员生还，英雄归来 |
| 70-89% | A级 | 大部分船员生还，凯旋而归 |
| 50-69% | B级 | 半数船员生还，代价沉重 |
| 30-49% | C级 | 少数船员生还，惨胜 |
| 0-29% | D级 | 几乎全军覆没，孤独归来 |
| 0% | E级 | 无人生还，沉没的堡垒 |

**结局评分公式**:
```
船员存活率得分 = 存活率 × 50（满分50分）
NPC船员好感度加分 = 各NPC加分之和（满分60分，6个NPC各10分）
任务完成度得分 = 完成主线任务数 × 10（满分50分）
资源积累得分 = 最终金币数 / 100（上限40分）

总分 = 船员存活率得分 + NPC好感度加分 + 任务完成度得分 + 资源积累得分
总分范围 0-200分
```

## Formulas

### 设施效率计算

```
facility_efficiency(facility) = base_efficiency × min(1.0, assigned_healthy / optimal_crew)

# 示例: 炮台(optimal=2)，分配1人
efficiency = 100% × min(1.0, 1/2) = 50%

# 示例: 维修(optimal=3)，分配3人
efficiency = 100% × min(1.0, 3/3) = 100%
```

### 士气对设施效率的修正

```
final_efficiency = base_efficiency × crew_ratio × morale_modifier

morale_modifier by range:
  90-100: 1.15  (+15%)
  70-89:  1.00  (+0%)
  50-69:  0.90  (-10%)
  30-49:  0.75  (-25%)
  0-29:   0.50  (-50%)
```

### 打捞成功率

```
salvage_rate = clamp(
    0.60
    - (depth / 100.0) × 0.10
    + equipment_level × 0.05
    + (is_npc_crew ? 0.20 : 0)
    + weather_modifier
    + (luck_value / 10) × 0.05,
    0.10,  # min 10%
    0.95   # max 95%
)
```

### 船员死亡数

```
crew_deaths = crew_on_submarine × death_probability(depth) × random_factor(0.8-1.2)
```

## Edge Cases

1. **船员数量为0**: 所有设施无法运作（0%效率），船无法移动，游戏接近不可玩状态。仍可招募恢复。
2. **船员总数超过maxCapacity**: 招募时检查，超过容量拒绝招募，提示"居住舱容量已满，升级居住舱后可招募更多"。
3. **士气降至0**: 触发"崩溃"状态，每10分钟有5%概率一名船员叛逃，直到士气恢复。
4. **NPC船员离开的剧情影响**: NPC船员离开后，其关联剧情线中断，特殊加成永久消失，可能触发其他NPC悲伤事件。
5. **打捞进行中船只再次被攻击**: 打捞过程不中断，但打捞成功率受当前船只状态影响（船只受损-10%成功率）。
6. **所有船员都在受伤状态**: healthy=0，所有设施0%效率，必须等待恢复或使用医疗室加速。
7. **船员事件与波次同时触发**: 船员事件延迟到波次结束后弹出，避免战斗中分心。
8. **自动分配时设施数量超过船员数**: 按优先级分配，低优先级设施不分配船员。
9. **船员统计与存档同步**: 船员数据（total/healthy/injured/dead/assignments/morale）全部存入存档系统。
10. **MVP不做船员个体化**: 船员只有数量没有名字/头像，后续V1.0可扩展。

## Acceptance Criteria

- [ ] 船员数据结构包含total/maxCapacity/healthy/injured/dead/morale字段

- [ ] 设施效率 = 基础效率 × min(1.0, 分配健康船员数 / 最优船员数)

- [ ] 船员事件（生病/叛逃/冲突等）在波次结束后弹出
