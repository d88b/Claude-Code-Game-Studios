## Phase 0：素材准备（3-5天）

> **核心理念：先用代码生成画面，再逐步替换成美术素材。**
> **目标**：7天内让游戏"看起来像游戏"。
> **参考文档**：`深海堡垒-素材制作指南.md`

### 素材方案总则

| 素材类型 | 推荐方案 | 原因 |
|---------|---------|------|
| 天空/海水 | **Shader程序生成** | 零成本、动态效果、随时可调 |
| 海底地形 | **免费TileMap素材包** | itch.io现成的，直接导入Godot |
| 船/潜艇 | **AI生成**（AutoGLM） | 核心视觉，出图快 |
| 敌人 | **先用方块占位 → 后期AI** | MVP不需要好看 |
| UI元素 | **Godot内置StyleBox** | 纯代码做，不需要外部素材 |
| 特效 | **Godot粒子系统** | 程序生成 |

### 0.1 第一批：程序生成素材（第1天，2小时内搞定）

> **不用任何图片，纯代码/Shader生成，立即看到画面。**

#### ① 动态海面Shader（5分钟）

```glsl
# 保存为: shaders/ocean_surface.gdshader
shader_type canvas_item;
uniform float wave_height = 15.0;
uniform float wave_speed = 2.0;
uniform vec4 water_color : source_color = vec4(0.0, 0.4, 0.7, 1.0);

void vertex() {
    VERTEX.x += sin(VERTEX.x * 0.05 + TIME * wave_speed) * wave_height;
    VERTEX.y += cos(VERTEX.x * 0.03 + TIME * wave_speed * 0.7) * wave_height * 0.5;
}

void fragment() {
    COLOR = water_color;
}
```

#### ② 天空渐变Shader（5分钟）

```glsl
# 保存为: shaders/sky_gradient.gdshader
shader_type canvas_item;
uniform vec4 top_color : source_color = vec4(0.2, 0.5, 0.9, 1.0);
uniform vec4 bottom_color : source_color = vec4(0.6, 0.8, 1.0, 1.0);

void fragment() {
    COLOR = mix(bottom_color, top_color, UV.y);
}
```

#### ③ 船体占位（10分钟，ColorRect拼）

| 组件 | Godot节点 | 尺寸 | 颜色 |
|------|----------|------|------|
| 船上层 | ColorRect | 400×80 | 灰色(#888) |
| 船中层 | ColorRect | 500×100 | 灰色(#777) |
| 船下层 | ColorRect | 450×120 | 深灰(#555) |
| 炮台 | ColorRect | 30×30 | 深灰(#444) |
| 船头三角 | Polygon2D | 三角形 | 灰色 |

#### ④ 潜艇占位（2分钟）

| 组件 | Godot节点 | 尺寸 |

#### ⑤ 海底地面（10分钟）

| 层 | 节点 | 说明 |

| 海水渐变 | ColorRect + Shader | 浅蓝→深蓝 |

**✅ 第1天验收**：打开Godot，能看到有天空、海水、船、潜艇、海底的完整场景！

> **目标**：从零到第一个可玩的完整循环 —— 航行→探索→建造→防守→下一海域。

## 开发顺序决策原则

### 每个阶段遵循的规则

1. **纵向切割优先于横向扩展**
   - 先让一个完整的循环能跑（即使粗糙）
   - 再往循环中添加内容和细节
   - ❌ 不要先做100种敌人的美术再写代码
   - ✅ 先用方块代替敌人，确保玩法好玩

2. **可玩 > 好看**
   - MVP阶段用占位图即可
   - 核心循环验证通过后再投入美术资源
   - 每个功能先实现"能用"，再做"好看"

3. **依赖驱动排序**
   - A依赖B → 先做B
   - 例如：Boss战依赖敌人AI → 先做敌人AI
   - 例如：交易依赖经济系统 → 先做经济框架

4. **反馈闭环优先**
   - 先做能给玩家即时反馈的系统
   - 建造→打怪→获得资源→升级→能打得更好
   - 这个反馈链要尽早打通

### 占位符策略

| 系统 | MVP占位符 | 正式版替换 |
|------|----------|-----------|
| 敌人 | 红色方块 | 100种敌人Sprite |
| 船 | 灰色矩形+分层 | 精细船体美术 |
| 潜艇 | 蓝色椭圆 | 精细潜艇美术 |

| UI | 基础Label | 完整UI+动画 |

## 关键风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 核心循环不好玩 | 项目方向错误 | Phase 1结束前必须验证，不好玩就调整 |
| 美术资源跟不上 | 开发阻塞 | 先用占位符，美术后期补 |
| 性能问题 | 大规模敌人卡顿 | Phase 2就开始做对象池，不要等到Phase 4 |
| 范围蔓延 | 项目永远完不成 | 严格按Phase优先级，V2.0功能一律不做 |
| 数值不平衡 | 游戏太简单/太难 | 每周调整一次数值，记录每次改动 |
